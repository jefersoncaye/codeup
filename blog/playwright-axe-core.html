Acessibilidade & Automação

Playwright + Axe-core: automação de testes de acessibilidade

Por Jeferson Caye · CodeUp

O que é acessibilidade digital?

Acessibilidade digital é o direito de qualquer pessoa usar uma aplicação web ou mobile, independentemente de ter deficiências visuais, auditivas, motoras ou cognitivas. Não é um extra ou um "nice to have" — é um requisito legal em muitos países e uma responsabilidade ética de quem constrói software.

As diretrizes WCAG 2.1 (Web Content Accessibility Guidelines) definem padrões internacionais de acessibilidade. Mas implementar tudo isso manualmente durante desenvolvimento é difícil e propenso a erros. É aí que entra a automação com axe-core.

O que é axe-core?

O axe-core é um motor de testes de acessibilidade open-source mantido pela Deque Systems. Ele analisa automaticamente uma página web ou componente e identifica violações de WCAG, gerando um relatório estruturado em JSON com o tipo de problema, severidade e instruções para corrigir.

O grande diferencial: você integra axe-core direto no seu framework de testes (Playwright, Cypress, Selenium) e roda a cada build, travando o pipeline se encontrar problemas críticos.

Por que automatizar testes de acessibilidade?

  • Detecção precoce: identificar problemas de acessibilidade durante o desenvolvimento é muito mais barato do que após o deploy.
  • Conformidade legal: muitos países têm leis obrigando acessibilidade (Lei de Acessibilidade na Web no Brasil, ADA nos EUA, EAA na Europa).
  • Melhor experiência para todos: usuários com e sem deficiências se beneficiam de uma interface acessível.
  • Alcance maior: seu produto fica disponível para mais pessoas, aumentando sua audiência.
  • SEO melhorado: boas práticas de acessibilidade (semântica HTML, contraste, etc) também melhoram SEO.

Testes de acessibilidade com Playwright e axe-core

Ao integrar axe-core com Playwright, você consegue automatizar testes de acessibilidade usando a mesma ferramenta que já usa para testes funcionais. Uma única suite cobre UI, API e acessibilidade.

Principais benefícios dessa combinação

  • Execução em contexto real: testa a página exatamente como aparece no browser, com JavaScript renderizado e estados da aplicação reais.
  • Seleção inteligente: roda axe apenas em componentes específicos, páginas inteiras ou com regras customizadas (WCAG, Seção 508, etc).
  • Relatórios estruturados: recebe JSON com violações categorizadas por severidade (critical, serious, moderate, minor).
  • Integração com CI/CD: gera artefatos do pipeline, publica relatórios HTML e trava builds automáticamente.
  • Fixtures reutilizáveis: compartilha fixtures do Pytest com fixtures de acessibilidade, login persistido, dados de teste, etc.
  • Helpers de assertion: cria assertions customizadas que verificam severidade de violações específicas.

Casos de uso no mundo real

  • Testar checkout de e-commerce: verifique se contraste, ordem de headings, labels e buttons estão acessíveis.
  • Validar leitores de tela: simule navegação via teclado e NVDA em fluxos críticos.
  • Scanear componentes isolados: teste um modal, form ou dropdown em acessibilidade antes de usar em qualquer página.
  • Gerar gates de acessibilidade: trave a publicação de uma feature se aparecer violação crítica.

Acessar Curso Grátis

O que você vai aprender

Este curso combina prática e teoria, começando do zero e evoluindo até pipelines profissionais:

Fundamentos (Seções 1-3)

  • Entender WCAG, os limites da automação e quando usar axe-core.
  • Ler e interpretar relatórios JSON do axe-core.
  • Configurar axe-core com Playwright e Pytest, organizando com fixtures de login, helpers de assertion e Page Object Model.

Execução avançada (Seções 4-5)

  • Rodar axe de formas diferentes: página inteira, componente isolado, regras específicas incluídas ou excluídas.
  • Identificar bugs reais em contraste, ordem de headings, landmarks duplicados, links só por cor e botões sem nome.

Testes que a automação não enxerga (Seção 6)

  • Navegar uma aplicação usando apenas teclado.
  • Testar com leitores de tela reais (NVDA) incluindo foco perdido após ações.

Pipeline e CI/CD (Seção 7)

  • Publicar um gate de acessibilidade no GitHub Actions que trava o build em violações críticas.
  • Arquivar relatórios estruturados como artefatos do pipeline.

Para quem é este curso?

  • QAs que usam Playwright e querem adicionar acessibilidade à sua estratégia de testes.
  • Desenvolvedores que precisam garantir que suas features sejam acessíveis desde o início.
  • Times que têm requisitos legais de conformidade WCAG.
  • Profissionais que querem se especializar em um tópico cada vez mais demandado no mercado.

Este curso é completamente grátis na Udemy. O objetivo é trazer mais profissionais para a comunidade de automação de testes e mostrar que acessibilidade não é complicada, é só questão de conhecer as ferramentas certas.
